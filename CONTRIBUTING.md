# Contributing to Breacán

Breacán is Apache-2.0. A contribution you intentionally submit is under the same license, as [section 5 of the license](https://www.apache.org/licenses/LICENSE-2.0#contributions) says. There is nothing to sign.

You keep the copyright in what you write, and the git history records who wrote what. The project itself is William Tierney's.

## Make a change

- `mise run setup`, then `mise run test`.
- Commits follow [Conventional Commits](https://www.conventionalcommits.org/); release-please builds the changelog
  and version from them.
- Source files start with the SPDX header below. `mise run reuse` checks it, and CI runs it.
- `mise run license` fails on any production dependency with a copyleft or unreadable license. Do not add one.
- `AGENTS.md` lists the rules that matter (frozen goldens, generated headers, the module shape).

```
// SPDX-FileCopyrightText: <year> <your name>
//
// SPDX-License-Identifier: Apache-2.0
```

A new file carries its author's name, and an edited file keeps its existing line.

A file that cannot carry a header (JSON, generated output, a golden) is covered in `REUSE.toml`. Third-party code
needs its own license and an entry in `NOTICE`.

## Update the Material tokens

`material/` is generated by `scripts/vendor-m3.mjs` from the Compose Material 3 token files in [androidx/androidx](https://github.com/androidx/androidx), at the commit recorded in `material/manifest.json`. Never edit it by hand. CI runs `bun scripts/vendor-m3.mjs --check` to hold it to that commit.

1. On a branch, run `bun scripts/vendor-m3.mjs --sha <androidx sha>`.
2. Review the diff.
3. Run `bun test`.
4. Open a pull request.

A Kotlin form the script does not know fails, naming the file and line.
