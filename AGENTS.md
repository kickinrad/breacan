# breacan

Builds DTCG 2025.10 `tokens/*.tokens.json` into stack targets, shipped as one standalone Bun binary per GitHub Release. Projects install it with `mise use github:kickinrad/breacan` and configure it in `breacan.config.mjs`.

## Commands

- `mise run setup`, then `mise run test`.
- `mise run build`, then `BREACAN_BIN=dist/breacan bun test` to test the compiled binary.

## Rules

- The CLI is `breacan build | check | lint | audit | dev | --version`. Until the Plan's contract task, it also answers to `kumiko`, no verb, `--check` and `kumiko.config.mjs`; keep those working.
- Generated headers still say "Generated by kumiko". Changing them makes every consumer's check fail until it rebuilds, so they move with the consumers.
- Every part outside the engine is a module `{ slot, name, reads, writes, run(ctx) → [{ path, content }] }` (`src/modules.mjs`). A built-in output is in `src/outputs/` and listed in `src/outputs/index.mjs`; a project's own is a module its config imports and lists as an object. A preset is a named list of built-ins.
- `tests/expected/` is frozen from the design-system 2.1.0 template, and `tests/kits/*.golden.json` from the real kits at d0d1c10. A byte change there is never silent: the PR says why. It is breaking (`!`) only when it renames or removes a name a kit's consumers read.
- Releases come from release-please on `main`. The release job attaches `breacan-linux-x64.tar.gz`, which holds the binary as both `breacan` and `kumiko`.
- `material/` is generated by `scripts/vendor-m3.mjs` from androidx (Apache-2.0) and loaded by `include: ["builtin:material"]`; never edit it. It holds Material's tokens only, nothing of any kit.
- The work in flight is `plans/breacan_plan.md`.
